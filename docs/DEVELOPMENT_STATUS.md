# 开发状态与交接记录

## 已完成并在代码中确认

- Tauri 2 + React + TypeScript + Vite 的 Windows 桌面项目骨架。
- 原创深色战术终端界面，包含配装评估、我的收藏、装备库、设置/关于四个页面。
- 页面纵向滚动和五档字体大小；“中”为默认值。
- 修正竖排槽位标签方向，提高中文字体可读性。
- 护甲、主武器、副武器、手雷、4 个战备和被动的完整选择流程。
- 阵营、1–10 难度和任务场景选择。
- 八维本地评分、缺口提示、封顶、规则命中和单槽替换建议。
- 双语/别名搜索、定位筛选和仅已解锁筛选。
- 装备库六个栏目：护甲、主武器、副武器、手雷、战备、被动。
- 战备分为轨道、飞鹰、蓝色和绿色四组，并在选择器与装备库中提供筛选。
- 本地收藏、载入和删除。
- `HD2T1` 分享码生成、CRC32 校验、压缩和 16KB 解码限制。
- AI 设置、Windows Credential Manager 存储、端点限制、30 秒超时、取消、结构校验和本地缓存的基础实现。
- 签名目录更新、摘要校验、版本指针、上一版本保留和诊断日志导出的 Rust 基础实现。
- 主武器/副武器详情按钮和右侧详情栏样式。
- AR-23 解放者作为第一条人工核验武器数据样板；未收录武器明确显示“资料待核验”。
- 本地 Wiki 图片索引生成工具；输出目录由 `.gitignore` 排除，不发布许可不明素材。
- 目录、评分、分享码、战备分组、字体大小和武器详情的基础单元测试。

## 当前明确缺口

- 武器详情事实目前只完整录入 AR-23 解放者，主武器和副武器尚未全量覆盖。
- 武器详情当前使用程序生成的示意图，不是 Wiki/游戏原图。
- 战备和被动未使用真实游戏图标；在取得明确再分发授权前必须继续使用占位图形。
- 内置目录虽然已有各槽位数据，但“发布时全部战斗相关内容”的完整性仍需逐项核对当前游戏版本。
- Wiki 数据需要至少两处可信来源或游戏内实测交叉核验，并记录核验日期/版本。
- 分享码测试尚未完整覆盖未知装备、旧版本迁移和全部非法组合。
- AI 缺少完整的超时、取消、恶意/非 JSON、未知候选和密钥泄漏回归测试。
- 数据更新缺少签名失败、下载中断、模式不兼容、原子替换失败和回滚的完整自动化测试。
- 各阵营、难度层级和典型任务的黄金配装夹具尚未建立。
- 键盘焦点圈闭、全页面导航、1280×720 和各字体档位仍需系统性 UI 验收。
- GitHub Actions 的 Windows x64 CI 尚未加入仓库。
- 正式数据清单、公钥、GitHub Release 数据包和 Tauri 更新发布流程尚未配置。
- Windows 代码签名尚未配置；未来测试安装包需要在 Release 中提示 SmartScreen。

## 下一步优先级

1. 建立武器事实数据录入模板和来源审查清单。
2. 分批补齐主武器、副武器详情，并为每批数据增加测试。
3. 明确每张 Wiki/游戏图片的再分发许可；无法确认时继续使用原创占位图。
4. 扩充分享码、AI、数据更新和黄金配装测试。

## 不得忘记的用户决定

- 不要在每次修改后生成安装包。
- 装备库详情侧栏采用“上方武器视觉区域、下方核心参数与来源”的已审核样式。
- 战备四分组含义固定：轨道、飞鹰、蓝色支援/载具、绿色炮台/防御。
- 真实战备和被动图像必须先解决公开再分发权利，不能因为 Wiki 页面可访问就直接提交原图。
- 评分由本地规则决定；AI 不能改分。

## 每次任务结束时的交接清单

- 更新本文件中的已完成项、缺口和下一步。
- 记录数据来源、核验版本和仍待确认之处。
- 运行 `pnpm test` 与 `pnpm build`，记录失败原因。
- 确认未加入凭据、`.env`、日志、构建产物或许可不明素材。
- 只有收到明确指令时才提交、推送、创建 PR 或生成安装包。
